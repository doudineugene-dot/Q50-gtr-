# Архитектура данных автомобиля

UI не участвует. Приборная панель читает только `VehicleData` и не знает, кто
её заполнил — именно поэтому подключение машины не потребовало ни одной
правки в утверждённом визуале.

## Слои

```
InTouchVehicleSource ─┐
EcuTekLiveSource     ─┼─> DataHub ──> VehicleData ──> DashboardView
AirLiftLiveSource    ─┤                  (Channel)
DemoDataProvider     ─┘
```

Источники не конкурируют за все параметры разом: каждый пишет только свои
каналы.

## Кто какой параметр даёт

| Параметр | Источник | Состояние |
|---|---|---|
| RPM | InTouch | подтверждён |
| Скорость | InTouch | подтверждён |
| Температура ОЖ | InTouch | подтверждён |
| Температура масла | InTouch | подтверждён |
| Давление масла | InTouch | подтверждён, множитель требует проверки на моторе |
| Дроссель | InTouch | кандидат: имя не наблюдалось |
| Наддув (факт) | InTouch, иначе EcuTek | кандидат |
| Температура впуска, наружная, борт. сеть, АКПП | InTouch | кандидаты |
| Детонация по цилиндрам, Knock Retard | EcuTek | транспорт не найден |
| AFR B1/B2, STFT/LTFT | EcuTek | транспорт не найден |
| Наддув (цель), УОЗ, HPFP | EcuTek | транспорт не найден |
| Давления пневмоподвески | AirLift | вне этого этапа |
| LPFP | — | UNAVAILABLE, не логируется |

«Кандидат» значит: имя сигнала правдоподобно, но на этой прошивке не
наблюдалось. Если сенсора нет, строка таблицы просто не сработает и канал
останется UNAVAILABLE. Выдумать значение она не может по построению.

## Channel: значение плюс его достоверность

У каждого параметра есть значение, отметка времени, источник и статус:

| Статус | Когда | Рисуется |
|---|---|---|
| `VALID` | пришло свежее реальное значение | да |
| `STALE` | было живым, но обновления нет дольше таймаута | да, но помечено |
| `DEMO` | синтетика для отладки UI | да, с отметкой DEMO |
| `UNAVAILABLE` | источника нет или канал не логируется | нет, «—» |
| `ERROR` | транспорт жив, но канал отдал ошибку | нет, «—» |

`ERROR` намеренно не рисуется: держать последнее число при известной ошибке —
это показывать водителю устаревшее значение как текущее.

## Таймауты

Свои у каждого сигнала (`VehicleSignal`):

| Класс | Таймаут |
|---|---|
| Быстрые: RPM, наддув, дроссель | 1.5 с |
| Средние: скорость, давление масла | 2 с |
| Медленные: температуры, напряжение | 10 с |

## Частоты опроса

Запрашиваются у `SensorManager` в микросекундах; на API 9 это подсказка, а не
гарантия, поэтому фактическую частоту показывает диагностический оверлей.

| Класс | Запрашиваем |
|---|---|
| Быстрые | 50 000 мкс (20 Гц) |
| Средние | 100 000 мкс (10 Гц) |
| Медленные | 500 000 мкс (2 Гц) |

Отрисовка — 20 кадров в секунду. На кадр ничего не выделяется: таблица
сигналов статична, шейдеры кэшируются, оверлей выключен.

## Главное правило LIVE

**Отсутствующий реальный параметр никогда не подменяется демо-значением.**

Реализовано защёлкой в `DataHub`: как только любой живой источник дал первый
кадр, демо выключается до перезапуска приложения, а демо-значения, успевшие
попасть в каналы на старте, снимаются (`VehicleData.clearDemoValues`). Иначе
кратковременный обрыв связи вернул бы на приборку выдуманные числа ровно
тогда, когда они опаснее всего.

## Только чтение

Ни один источник ничего не отправляет в машину. Нет передачи CAN, записи в
ECU, кодирования, UDS-записи, сброса ошибок, прошивки и команд AirLift.
`InTouchVehicleSource` вызывает только `getSensorList`, `registerListener` и
`unregisterListener`.
