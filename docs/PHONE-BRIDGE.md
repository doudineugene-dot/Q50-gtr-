# Мост через телефон: протокол приёмника

> **Состояние: работает. Проверено на автомобиле в обе стороны.**
>
> ```
> ГУ → телефон:  From 10.174.142.45:50784
>                Q50GTR BEACON 10.174.142.45 PORT 45455
> телефон → ГУ:  ПРИЁМ: UDP 45455  пакетов>0  от 10.174.142.156
> ```
>
> Раньше здесь стояло «невозможен»: в ядре было ровно два сетевых
> устройства, `audio0` и `lo`, а Wi-Fi-железа нет вовсе. Это остаётся
> правдой — но неполной. Модуль `rndis_host` нашёлся на диске прошивки, и
> с ним телефон в режиме USB-модема даёт ядру полноценный `usb0`. Вывод
> «сети нет» был верен для того, что уже загружено, и неверен для того,
> что загрузить можно.

Прямой путь с ГУ до EcuTek закрыт (`docs/ECUTEK-EVI-6087.md`): адаптер BLE,
а публичного BLE API в Android до API 18 нет, здесь API 10. Телефон же и BLE
умеет, и с OBD-адаптером по классическому Bluetooth разговаривает. Значит
читает телефон, а ГУ показывает.

Приёмник на стороне ГУ **сознательно не знает ни про EcuTek, ни про
ELM327**. Протокол EcuTek до сих пор не разобран, и привязывать к нему
приёмник значило бы снова упереться в неизвестное. Формат здесь свой,
описанный полностью.

## Как поднимается канал на ГУ

Доказано на машине: телефон в режиме USB-модема перечисляется на шине
(`SAMSUNG SAMSUNG_Android`), драйвер `rndis_host` его подхватывает, ядро
создаёт интерфейс `usb0`.

Дальше интерфейсу нужен адрес — сам он его не получает.

**Адрес берётся по DHCP, а не задаётся статически.** Сначала было
наоборот, и это стоило нескольких поездок: статика опиралась на
«Android при раздаче занимает `192.168.42.129`». Для этого телефона
неверно. Замер:

```
подсеть : 10.174.142.0/24
телефон : 10.174.142.156
ГУ      : 10.174.142.45   (в разные сессии .12, .106, .168, .45)
```

Подсеть выдаёт телефон, и она произвольна. Всё, что уходило на
`192.168.42.x`, уходило в чужую сеть — при исправном проводе, поднятом
интерфейсе, нулевых ошибках передачи и маршруте на месте. Снаружи это
выглядело как «связи нет», и перебирать причины можно было бесконечно.
Различила их не догадка, а три измерения: `carrier` из `/sys`, прирост
счётчиков `/proc/net/dev` и незавершённая запись ARP с нулевым MAC.

Адрес ГУ меняется при каждом подключении, поэтому вписать его в
инструкцию нельзя. Отсюда **маяк**: ГУ раз в секунду шлёт
широковещательно

```
Q50GTR BEACON <свой адрес> PORT 45455
```

Телефону достаточно слушать порт 45455 — адрес придёт сам. Приложению-мосту
не нужно ни настройки, ни ввода: услышал маяк, взял адрес, отвечает на него.

Всё это делает кнопка на странице МОСТ, которая ведёт по шагам:

```
1. ЗАГРУЗИТЬ RNDIS_HOST (root)
2. ПОДКЛЮЧИТЕ ТЕЛЕФОН, ВКЛЮЧИТЕ USB-МОДЕМ
3. ПОДНЯТЬ usb0 (root)        — сначала DHCP, статика только запасной путь
4. ПРОБА ПЕРЕДАЧИ
5. МАЯК
```

Команды временные: на диске ничего не меняется, после выключения зажигания
и драйвер, и адрес исчезают. Теперь, когда канал доказан, автозапуск этих
шагов при старте приложения имеет смысл делать.

## Чего на телефоне быть не должно

Проверено на машине, оба случая выглядят одинаково — «отправил, не дошло»:

- **VPN.** Android уводит в туннель трафик всех приложений. Пакет на
  `10.174.142.x` до кабеля не доходит никогда. Признак — ключ в строке
  состояния и чужой адрес в поле Local IP (`10.193.204.66`, `12.18.60.127`).
- **Адрес из прошлой сессии.** DHCP выдаёт новый каждый раз; маяк
  избавляет от этой ошибки совсем.

## Формат

```
транспорт : UDP
порт      : 45455
тело      : текст UTF-8, по строке на параметр
строка    : КЛЮЧ=ЧИСЛО
```

Пример датаграммы:

```
RPM=1734.0
BOOST=0.62
AFR_B1=12.4
IGNITION=14.5
KI1=0.0
KI2=0.3
```

Слать можно с любой частотой; разумно 10–20 раз в секунду для быстрых
величин. Каждая датаграмма самодостаточна: присылать весь набор каждый раз
не обязательно, не пришедшие ключи просто сохраняют прежнее значение и
уходят в STALE через две секунды.

## Ключи

| ключ | канал | единица |
|---|---|---|
| `RPM` | обороты | rpm |
| `SPEED` | скорость | км/ч |
| `BOOST` или `BOOST_ACTUAL` | наддув факт | бар |
| `BOOST_TARGET` | наддув цель | бар |
| `AFR_B1`, `AFR_B2` | смесь по банкам | AFR |
| `IGNITION` или `IGN_TIMING` | угол опережения | ° |
| `KNOCK_RETARD` | коррекция по детонации | ° |
| `KI1`…`KI6` | Knock Index по цилиндрам | — |
| `HPFP` или `HPFP_ACTUAL`, `HPFP_TARGET` | ТНВД | бар |
| `STFT_B1`, `STFT_B2`, `LTFT_B1`, `LTFT_B2` | коррекции топлива | % |
| `THROTTLE` | дроссель | % |
| `COOLANT_TEMP`, `OIL_TEMP`, `INTAKE_TEMP`, `TRANS_TEMP` | температуры | °C |
| `VOLTAGE` | бортсеть | В |
| `AIR_FL`, `AIR_FR`, `AIR_RL`, `AIR_RR` | давление в подушках | бар |
| `AIR_TANK` | давление в ресивере | бар |

### Единицы давления: два имени на один канал

Air Lift считает в psi, а приборка показывает бары. Перепутать их легко, и
цена ошибки высокая: 36 psi — это 2.5 бара, а 36 бар — разорванная подушка.
Поэтому единица задаётся **именем ключа**, а не догадкой на приёмной
стороне. К любому ключу давления можно дописать `_PSI`:

```
AIR_FL=2.48        # бары
AIR_FL_PSI=36.0    # то же самое в psi, ГУ пересчитает
```

Значения вне 0..16 бар отбрасываются: это либо чужие единицы, либо мусор.

### Зарезервировано под 3H

Система 3H меряет ещё и высоту по всем четырём углам. Ключи
`AIR_H_FL`, `AIR_H_FR`, `AIR_H_RL`, `AIR_H_RR` зарезервированы за ней, но
пока не привязаны: на утверждённом экране ШАССИ для высот места нет, а
менять его без отдельного решения нельзя. Слать их можно уже сейчас —
неизвестные ключи молча пропускаются.

Неизвестные ключи молча пропускаются: отправитель вправе слать больше, чем
ГУ умеет показать.

## Проверки на стороне ГУ

Приёмник открыт в сеть, поэтому значения вне физически возможного диапазона
отбрасываются: обороты вне 0..9000, скорость вне 0..400, AFR вне 5..25,
наддув вне −1.5..4, температуры вне −60..200. На приборке автомобиля лучше
прочерк, чем мусор из сети.

**Данные идут только в одну сторону.** Сокет открыт на приём; ни в сторону
телефона, ни тем более в сторону автомобиля отсюда не уходит ничего.

## Приоритет источников

Мост опрашивается после штатной шины. Там, где параметр есть у обоих,
побеждает мост: он несёт данные уровня ECU, которых на шине ГУ либо нет
вовсе, либо они грубее. Если мост замолчал дольше двух секунд, его каналы
уходят в STALE, а штатные продолжают жить своей жизнью.

## Что показывает ГУ

На первой странице диагностического оверлея появились строки:

```
МОСТ: UDP 45455  пакетов=0
АДРЕС ГУ: 192.168.x.x
```

`АДРЕС ГУ` — то, что нужно вбить в отправителе на телефоне. Если там
написано «сети нет», у головного устройства нет ни одного сетевого
интерфейса, и мост в этом виде невозможен — это выяснится до того, как
будет написана хоть строчка телефонного приложения.

## Что дальше на стороне телефона

Два источника, и они независимы.

**EcuTek EVI по BLE.** Наддув, AFR по банкам, Knock Index по цилиндрам,
угол опережения, ТНВД, коррекции топлива.

**Air Lift 3H по BLE.** Давления в четырёх подушках и ресивере. На этом
этапе — **только чтение**: ни одной команды в подвеску не отправляется.
Управление высотой не делаем, и это осознанно — в собственном приложении
Air Lift дистанционное управление работает только на заглушенной машине.

Обычный OBD (ELM327) из планов исключён по решению пользователя.

Оба источника упираются в неразобранный протокол, и ни один из них
публично не документирован. Нужен `btsnoop_hci.log` с телефона. Хорошая
новость: **одного сеанса записи хватит на оба** — достаточно в одном окне
записи поработать сначала ECU Connect, затем приложением Air Lift.
