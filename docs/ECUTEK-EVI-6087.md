# EVI-6087: что известно об этом конкретном адаптере

Данные сняты пользователем с экрана ECU Connect:

```
Name:              EVI-6087
Hardware:          EVI-BT R9
Main version:      5.0.0
Boot version:      2.0.1
Bluetooth version: 1.1.0
```

`Bluetooth version 1.1.0` — это версия прошивки радиомодуля, а не версия
спецификации Bluetooth. Никакого вывода о транспорте из неё не следует.

## Противоречие, которое нужно назвать прямо

Само изделие подписано **EVI-BT**, а EcuTek документирует EVI-BT как
классический Bluetooth, EVI-BTLE — как Bluetooth Low Energy
([EcuTek Support](https://ecutek.atlassian.net/wiki/spaces/SUPPORT/pages/557483/ECU+Connect+The+Bluetooth+Vehicle+interface)).
По названию — Classic.

Но там же сказано, что **ревизии железа с Rev 7 и выше — это BTLE**, а ниже
Rev 7 — классический Bluetooth. Наш адаптер — **R9**, то есть девятая
ревизия, заведомо выше седьмой. По ревизии — BTLE.

Два признака указывают в разные стороны. Правдоподобное объяснение: имя
изделия «EVI-BT» осталось прежним, а радиомодуль в поздних ревизиях сменили
на BLE — так бывает часто. Но это объяснение, а не доказательство:
страницы EcuTek напрямую из рабочей среды недоступны, и оба утверждения
получены пересказом поиска, возможно с одной и той же страницы.

**Ведущая версия: адаптер BLE.** Она опирается на ревизию, то есть на более
конкретный признак, чем название семейства.

## Почему это решает судьбу прямого пути

Публичный Bluetooth Low Energy API появился в Android в **API 18**. На
головном устройстве — **API 10**. BLE-стека там нет и быть не может.

Значит если адаптер действительно BLE, то соединиться с ним напрямую с ГУ
невозможно независимо от того, есть ли на ГУ Bluetooth-контроллер и разобран
ли протокол EcuTek.

## Как это проверить, не выезжая в машину

Есть признак, который виден с дивана. Классический EVI-BT нужно **сопрягать
в системных настройках Bluetooth телефона** — он появляется в списке
устройств и запрашивает код. BLE-устройство так не сопрягают: ECU Connect
соединяется с ним сам, и в списке сопряжённых телефона оно не появляется.

Поэтому: **откройте на телефоне настройки Bluetooth и посмотрите, есть ли
`EVI-6087` в списке сопряжённых устройств.**

* есть в сопряжённых → классический Bluetooth, прямой путь с ГУ возможен;
* нет, а ECU Connect при этом работает → BLE, прямой путь закрыт.

## Запасные пути, если подтвердится BLE

**USB-адаптер Bluetooth в порт ГУ.** Не годится. Android USB Host API
появился в API 12, здесь API 10; кроме того, потребовался бы драйвер в ядре
и стек Bluetooth в системе, которого, возможно, нет вовсе.

**Мост через телефон.** Телефон соединяется с EVI по BLE и пересылает данные
на ГУ по сети. Технически возможно, и зонд теперь заодно снимает сетевые
интерфейсы ГУ, чтобы знать, есть ли там вообще сеть. Но важно понимать:
мост снимает проблему транспорта и **не снимает проблему протокола**. Что
именно пересылать, по-прежнему неизвестно.

## Что остаётся на критическом пути в любом случае

Протокол ECU Connect. Без него ни прямой путь, ни мост не дают ни одного
значения. Нужен один из двух артефактов:

1. **`btsnoop_hci.log`** с телефона за сеанс работы ECU Connect с машиной;
2. либо **APK приложения ECU Connect**.

Лог предпочтительнее: он меньше, и он **одновременно отвечает на вопрос о
транспорте** — в HCI-логе видно, идёт обмен по BR/EDR (Classic) или по LE.
То есть один файл закрывает сразу оба открытых вопроса.

### Как снять btsnoop на Android

Проверено по устройству самого лога: он пишется системой, отдельных прав
приложению не нужно, но включается только в режиме разработчика.

1. «О телефоне» → семь раз нажать «Номер сборки» — включится режим
   разработчика.
2. «Для разработчиков» → включить **«Включить журнал HCI Bluetooth»**
   (на части прошивок — «Bluetooth HCI snoop log»).
3. Выключить и включить Bluetooth, чтобы журнал начал писаться.
4. Открыть ECU Connect, соединиться с EVI-6087 на заведённой машине,
   поработать **одну-две минуты**: дать приборам ожить, погазовать.
5. Выйти из ECU Connect, выключить журнал в настройках.
6. Забрать файл. Он лежит по одному из путей, зависит от прошивки:
   `/sdcard/btsnoop_hci.log`, `/sdcard/Android/data/btsnoop_hci.log`,
   либо внутри отчёта об ошибке: «Для разработчиков» → «Отчёт об ошибке» →
   в архиве файл `btsnoop_hci.log`.

Размер — единицы мегабайт. Его можно приложить прямо в переписку.
