# Штатный доступ к данным автомобиля на InTouch DCU Gen1

Итог: **API найден, и он штатный.** Головное устройство отдаёт шину как
обычные Android-сенсоры. Ни декомпиляции framework.jar, ни прямого CAN не
потребовалось.

Каждый факт ниже снабжён источником. Там, где источника нет, стоит «не
проверено» — и это не то же самое, что «работает».

## 1. Что искали и в каком порядке

По приоритету из задания: штатный vehicle API → системные сервисы → framework
классы → broadcast/provider → CAN gateway → прямой CAN → EcuTek. Ответ нашёлся
на первом уровне, поэтому ниже уровни 2–6 разобраны только в части
отрицательных результатов, которые закрывают тупики.

## 2. Найденный механизм

**Шина выведена в `android.hardware.SensorManager`.**

| Свойство | Значение |
|---|---|
| Вендор сенсоров | `Ygomi` |
| Имена | `VS_ID_*` |
| Типы | 12..53 |
| Разрешение | `com.ygomi.permission.IVI_CAN_READ` |
| Уровень разрешения | dangerous → на Android 2.3 выдаётся автоматически |

Вызов ровно такой:

```java
SensorManager sm = (SensorManager) getSystemService(SENSOR_SERVICE);
for (Sensor s : sm.getSensorList(Sensor.TYPE_ALL))
    sm.registerListener(this, s, rateUs);
// onSensorChanged(e): e.sensor.getName(), e.values[0]
```

**Источник:** `doudineugene-dot/q50`, файлы
`app/src/com/q50/info/CanSensors.java`, `dash/src/com/q50/dash/MainActivity.java`,
`docs/head-unit-findings.md`, `docs/can-signals.md`. Механизм независимо
подтверждён открытым проектом `qazwsd147/appgarage-dash` (ссылка на него есть
в шапке `CanSensors.java`).

**Проверено на этой машине:** да. `docs/head-unit-findings.md` фиксирует запуск
Q50 Info на живом ГУ: найдено **42 автомобильных сенсора, 39 с живыми данными**
при заглушённом двигателе.

## 3. Про разрешение IVI_CAN_READ

Задание требовало не считать наличие permission доказательством API. Не
считаем. Доказательство — не строка в манифесте, а наблюдение: приложение с
этим разрешением на этом ГУ получило 39 живых значений. Разрешение открывает
именно сенсоры Ygomi; никакого отдельного `CanManager`/`VehicleManager` в
найденных материалах нет, и приложение к нему не обращается.

| 13 | `VS_ID_ENGINE_RPM` | обороты | 0 |
| 14 | `VS_ID_ENGINE_COOLANT_TEMPERATURE` | температура ОЖ | 84 |
| 15 | `VS_ID_ENGINE_OIL_TEMPERATURE` | температура масла | 77 |

33 сигнала, про которые мы пока ничего не знаем. Их список снимет наш зонд
при первом запуске в машине — см. раздел 7.

## 5. Тупики, закрытые отрицательным результатом

Проверено на живом ГУ (`docs/head-unit-findings.md`), прямой CAN с
Android-стороны недоступен:

* `/proc/net/can` — нет, SocketCAN не поднят;
* модулей `can*` в `/proc/modules` — нет;
* CAN-интерфейсов (`type=280`) — нет, только `lo` и `audio0`;
* `/dev/can*` — нет;
* `candump` / `cansend` / `cangen` / `canconfig` — не установлены.

Поэтому пункты 5–6 приоритета задания (CAN gateway, прямой CAN) на этой
прошивке закрыты: писать CAN-парсер было бы некуда его подключить.

## 6. Границы штатного API

Чего в 42 сигналах нет и быть не может: **детонация, угол опережения
зажигания, AFR/лямбда, топливные коррекции, HPFP, положение вестгейта, фазы
валов**. ГУ этих параметров у мотора не запрашивает — оно вообще не опрашивает
ECU, а слушает то, что вещается на шине.

Это граница вендора, а не ограничение приложения. Такие параметры доступны
только опросом ECU (OBD режим 22, заводские PID Nissan) — то есть через
EcuTek или аналогичный внешний канал. См. `docs/ECUTEK-TRANSPORT-RESEARCH.md`.

Про наддув: в `dash/src/com/q50/dash/Signals.java` есть строки
`VS_ID_BOOST_PRESSURE` и `VS_ID_TURBO_BOOST`, но в подтверждённом списке
12–20 их нет. Считаем их кандидатами, не фактом.

## 7. Что осталось выяснить и как

Единственное белое пятно — имена сигналов типов 21–53. Отдельный файл с ГУ
для этого **не нужен**: `VehicleProbe` в нашем приложении перечисляет все
сенсоры и пишет в logcat раздел «есть на шине, но у нас нет привязки». После
первого запуска в машине список закроется, и таблицу
`VehicleSignal.TABLE` можно будет дополнить по факту, а не по догадке.

## 8. Что из этого реализовано

* `data/InTouchVehicleSource.java` — подписка на сенсоры, только чтение.
* `data/VehicleSignal.java` — таблица привязки с пометкой CONFIRMED/CANDIDATE.
* `data/VehicleProbe.java` — read-only перечисление источников.
