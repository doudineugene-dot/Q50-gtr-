# Q50 GTR+

Дополнительная приборная панель для штатного головного устройства
Infiniti Q50 2017 (InTouch / DCU Gen1).

**Версия:** 0.6 · **Экран:** 840×480, landscape

> Совместимость с DCU ещё **не проверена**: приложение собирается и
> подписывается, но на автомобиль пока не устанавливалось.

## Что это

Одно окно, три вкладки, вся графика рисуется программно через
`android.graphics.Canvas`. Ни AndroidX, ни support library, ни Material —
ни одной сторонней зависимости вообще. Ни одного layout XML.

### Вкладки

| ДВИГАТЕЛЬ | ТОПЛИВО | ШАССИ |
|---|---|---|
| RPM, Boost actual | HPFP actual/target | Силуэт Q50 сверху |
| Охлаждающая жидкость | AFR B1/B2 | Давление по 4 углам |
| Температура масла | STFT B1/B2 | Ресивер |
| Давление масла | LTFT B1/B2 | АКПП, раздатка |
| Температура впуска | Boost actual/target | Борт. сеть, наружная T |

Нижняя строка (всегда видна): ignition timing, максимальный knock index,
положение дросселя, скорость.

Навигация: касание вкладки или горизонтальный свайп.

## Источники данных

Отрисовка ничего не знает о происхождении чисел. Каждое значение — это
`Channel` со своим состоянием:

| Состояние | Смысл |
|---|---|
| `LIVE` | реальные данные из машины |
| `STALE` | были реальными, свежих кадров нет |
| `DEMO` | синтетика для проверки интерфейса, всегда с бейджем DEMO |
| `UNAVAILABLE` | канал не логируется — рисуется «НЕТ ДАННЫХ», не число |

`DataHub` отдаёт приоритет живым источникам; `DemoDataProvider` работает
только пока ни один из них не подключён.

- `EcuTekSource` / `EcuTekLiveSource` — заготовка под EcuTek.
- `AirLiftSource` / `AirLiftLiveSource` — заготовка под AirLift Performance 3H.

Транспорт ни для одного из них **не придуман**: обе реализации честно
сообщают `isConnected() == false` и не пишут ни одного значения. Подключение
реальных данных — это работа внутри `poll()`, приборная панель не меняется.

### Чего в логе нет

- **LPFP** — низкое давление топлива в текущей конфигурации EcuTek не
  логируется. Канал есть, но постоянно `UNAVAILABLE`, и вкладка ТОПЛИВО
  прямо говорит об этом.
- **Turbo Speed** — не логируется на этой машине, поэтому в проекте
  отсутствует полностью.

## Сборка

Локальный Android SDK не нужен — всё собирается в GitHub Actions:

1. Actions → **Build APK** → Run workflow (или любой push в `main`).
2. Artifact **`Q50-GTR-Plus-v0.6-APK`** со страницы завершённого run.
3. Внутри: `Q50-GTR-Plus-v0.6.apk` и `signature.txt`.

Workflow проверяет, что APK подписан **v1 (JAR signing)** — старый DCU
проверяет именно её, одной v2/v3 недостаточно.

### Подпись

Release собирается стандартным debug-ключом, который генерируется прямо на
раннере. В репозитории нет и не должно быть ни ключей, ни паролей. Для
production-ключа нужно завести GitHub Secrets и отдельный `signingConfig`.
